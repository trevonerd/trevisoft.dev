# Product

## Register

brand

## Users

Trevisoft serves people discovering Marco Trevisani’s side projects. Visitors should be able to see what each tool does and where to try it. Marco’s personal site has its own link in the footer.

## Product Purpose

Trevisoft is a name with family roots. Marco Trevisani publishes his personal software projects under that name: web apps, browser extensions, game tools, media utilities, creative generators, agent skills, and whatever ships next. The site should make the project collection feel alive and useful, while giving visitors enough context to trust the maker behind it. Success means a visitor can scan the work, open the right tool, and leave with a clear impression: Marco ships practical, polished, curious software.

## Brand Personality

Curious, precise, playful. The voice should feel technical but human, independent but not amateur, and quietly proud without becoming corporate. The moustache mark and synth-lab atmosphere are part of the identity, but they should feel calibrated rather than loud.

## Anti-references

Trevisoft should not feel like an overproduced neon arcade, a generic AI landing page, a noisy portfolio template, a cramped card wall, or a decorative effects demo where particles and glow compete with the projects. Avoid wrong spacing rhythms, excessive visual effects, inside jokes that obscure the projects, and anything that makes the page harder to scan.

## Design Principles

1. Show the tools first. Project utility, status, and actions should be obvious before decoration registers.
2. Earn the weirdness. Personality works best as a precise accent, not as a blanket treatment over every surface.
3. Give each project a clear description and a direct way to try it.
4. Calm the surface, keep the pulse. Preserve the synth identity while reducing visual noise, glow stacking, and spacing errors.
5. Make every project scannable. Categories, short descriptions, and specific actions help visitors find and open the right project.

## Accessibility & Inclusion

Use WCAG AA as the baseline for contrast, keyboard access, and focus visibility. Respect reduced-motion preferences, avoid relying on color alone for project meaning, and keep the easter egg nonblocking. The page should work for mobile browsing and visitors who skim with assistive technology.
